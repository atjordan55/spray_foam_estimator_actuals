PART A — Database (server.js):

1. In the initDatabase() function, after the existing table creation
   blocks, create a new table called material_inventory:

   CREATE TABLE IF NOT EXISTS material_inventory (
     id SERIAL PRIMARY KEY,
     material_type_id TEXT NOT NULL,
     material_type_name TEXT NOT NULL,
     material_category TEXT NOT NULL DEFAULT 'foam',
     gallons NUMERIC(10,2) NOT NULL,
     inventory_unit TEXT NOT NULL DEFAULT 'gallons',
     container_type TEXT,
     container_equivalent NUMERIC(10,4),
     cost_per_gallon NUMERIC(10,2) NOT NULL DEFAULT 0,
     source TEXT NOT NULL DEFAULT 'manual_addition'
       CHECK (source IN (
         'manual_addition',
         'initial_seed',
         'purchase_delivery',
         'job_surplus',
         'inventory_commitment',
         'commitment_reversal',
         'adjustment'
       )),
     committed_at TIMESTAMP,
     committed_to_estimate TEXT,
     source_estimate_name TEXT,
     source_job_date TEXT,
     notes TEXT,
     created_at TIMESTAMP DEFAULT NOW()
   )

   Field reference:
   - inventory_unit accepts: 'gallons', 'sets', 'buckets', 'drums'
   - container_type stores a description such as '110-gallon set'
     or '5 gallon bucket'
   - container_equivalent stores how many gallons one container
     represents, used for display and conversion
   - source is a controlled enum — the CHECK constraint enforces
     that only recognized values are stored. Any insert with an
     unrecognized source value must fail with a database error
     rather than silently storing bad data
   - committed_at records when an inventory_commitment transaction
     was created, enabling future reporting on reserved vs available
     stock and aging of committed material
   - committed_to_estimate pairs the commitment timestamp with the
     estimate name for traceability

2. Add four new API routes before the static file serving line:

   GET /api/inventory
   Returns all inventory entries ordered by created_at DESC.
   Response: { entries: [...all rows...] }

   GET /api/inventory/summary
   Returns available gallons grouped by material_type_id using
   SUM(gallons), only including groups where SUM(gallons) > 0.
   Also returns AVG(cost_per_gallon) for entries where gallons > 0
   per group, and the most common inventory_unit and container_type
   for that material type.
   Response: { summary: [{ material_type_id, material_type_name,
   material_category, available_gallons, avg_cost_per_gallon,
   inventory_unit, container_type }] }

   POST /api/inventory
   Accepts: material_type_id (required), material_type_name
   (required), material_category, gallons (required),
   inventory_unit, container_type, container_equivalent,
   cost_per_gallon, source, committed_at, committed_to_estimate,
   source_estimate_name, source_job_date, notes.
   Gallons may be positive (adding stock) or negative (consuming
   stock). Inserts a new row and returns the created entry.
   Response: { entry: {...} }

   DELETE /api/inventory/:id
   Deletes the entry with the given id.
   Response: { deleted: true }

5. Modify calculateFoamApplicationCost(area, foamApp):
   After calculating total gallons needed, check
   inventoryCredits[foamApp.foamTypeId]. If a credit exists:
   creditedGallons = Math.min(totalGallons, credit)
   paidGallons = totalGallons - creditedGallons
   costPerGallon = materialPrice / usableGallonsPerSet (default 100)
   effectiveMaterialCost = paidGallons * costPerGallon
     * (1 + materialCostPct / 100)
   Use effectiveMaterialCost as baseMaterialCost going forward.
   Include creditedGallons in the return object. All other
   calculations continue unchanged based on new baseMaterialCost.

6. After the loop computing baseMaterialCost across all spray areas,
   derive:

   totalInventoryCreditGallons:
   Sum of all values in inventoryCredits.

   totalInventoryCreditValue:
   For each foamTypeId in inventoryCredits, multiply credited
   gallons by avg_cost_per_gallon from the matching inventorySummary
   entry. Sum all results.

   to calculateFoamApplicationCost(area, foamApp, ignoreCredits).
   When ignoreCredits is true, creditedGallons is always 0 and
   paidGallons equals total gallons regardless of inventoryCredits
   state. When ignoreCredits is false (the default), behavior is
   identical to the current Phase 1 implementation. This parameter
   must not affect any existing call site since it defaults to false.

2. After the existing loop that computes baseMaterialCost across all
   spray areas, add a second parallel loop computing
   replacementMaterialCost. This loop is identical to the first
   except every call to calculateFoamApplicationCost passes
   ignoreCredits = true. For coating applications,
   replacementMaterialCost uses the identical value as
   baseMaterialCost since coatings are not part of the inventory
   credit system.

3. Derive replacement path profit variables alongside the existing
   operational path variables. Do not rename or remove any existing
   variables. Add new ones with a 'replacement' prefix:

   replacementMaterialMarkupAmount:
   Computed using replacementMaterialCost with the same markup
   percentage logic used for materialMarkupAmount.

   replacementTotalBaseCost:
   replacementMaterialCost + baseLaborCost + additionalJobCostBase

   replacementTotalJobCost:
   replacementTotalBaseCost + replacementMaterialMarkupAmount
   + laborMarkupAmount + additionalJobCostMarkup

   replacementCustomerCost:
   replacementTotalJobCost - discountDollar

   replacementNetProfitBeforeCommission:
   replacementCustomerCost - replacementTotalBaseCost

   replacementProfitMarginBeforeCommission:
   replacementCustomerCost > 0
   ? (replacementNetProfitBeforeCommission /
      replacementCustomerCost) * 100
   : 0

   replacementSalesCommission:
   Pass replacementNetProfitBeforeCommission and
   replacementProfitMarginBeforeCommission into the existing
   calculateSalesCommission function.

   replacementProfit:
   replacementCustomerCost - replacementTotalBaseCost
   - replacementSalesCommission

   replacementMargin:
   replacementCustomerCost > 0
   ? (replacementProfit / replacementCustomerCost) * 100
   : 0

4. Compute two inventory advantage display values. These are only
   meaningful when totalInventoryCreditGallons > 0:

   inventoryMarginAdvantage:
   profitMargin - replacementMargin (in percentage points, positive
   when credits are active)

   inventoryProfitAdvantage:
   estimatedProfit - replacementProfit (dollar difference)

5. In the estimate summary results panel apply these display rules:

   When totalInventoryCreditGallons is 0 (no credits active):
   Show one row labeled "Profit Margin" exactly as before. No

   When totalInventoryCreditGallons > 0 (credits active):
   Replace the single margin row with three elements:

   Row 1 — "Operational Margin" with tooltip icon.
   Tooltip: "Profit based on actual cash spent on this job.
   Inventory material applied as a credit is treated as $0 cost."
   Value: profitMargin % and estimatedProfit $ using the existing
   color thresholds (red/yellow/green).

   Between rows — green callout line:

   X = inventoryMarginAdvantage.toFixed(1)
   Y = inventoryProfitAdvantage.toFixed(2)

PHASE 3D — AKURATE LOG FILE IMPORT
════════════════════════════════════════════════════════════════

Context: The CoreSeal team uses Akurate Dynamics spray foam
equipment. The machine's control screen displays and logs: Gallons
ISO (A-side), Gallons Resin (B-side), Total Lbs, Ratio %, ISO
pressure, Resin pressure, ISO temperature, Resin temperature, and
Job #. The exact export file format may vary by firmware version,
so the parser must be tolerant and flexible rather than strict.
Never use alert() anywhere in this feature — all feedback must
be shown inline.

In src/App.jsx only:

1. Add two state variables near the existing actuals state:
   akurateImportMessage — string, default ''
   akurateImportMessageType — string, default ''
     Either 'success' or 'error', used to color the message.

2. Add a function parseAkurateLog(fileText):
   Receives the raw text content of an uploaded file. Returns an
   object containing any of these keys that were successfully
   identified and parsed:
   { isoGallons, resinGallons, totalLbs, ratioPercent,
     isoTemp, resinTemp, isoPressure, resinPressure, jobNumber }
   All values are parsed as numbers except jobNumber which is
   a string.

   Parsing strategy: split fileText into lines. For each line,
   apply case-insensitive matching that tolerates varied spacing,
   colons, equals signs, and tab delimiters between label and
   value. Match the following patterns:

   'gallons iso' or 'iso gallons'         → isoGallons
   'gallons resin' or 'resin gallons'     → resinGallons
   'total lbs' or 'total pounds'          → totalLbs
   'ratio' followed by a number           → ratioPercent
     (strip % signs before parsing)
   'iso temp' or 'temperature iso'        → isoTemp
   'resin temp' or 'temperature resin'    → resinTemp
   'iso psi' or 'iso pressure'            → isoPressure
   'resin psi' or 'resin pressure'        → resinPressure
   'job #' or 'job number' or 'job id'    → jobNumber

   If a value is found for a numeric key but cannot be parsed as
   a valid finite number, skip that key entirely rather than
   storing NaN or null. Return only keys where a valid value was
   found. Return an empty object if nothing was recognized.

3. Add a function handleAkurateImport(file):
   Reads the file as text using FileReader. On load, calls
   parseAkurateLog with the result text. Counts fields found.

   If 0 fields found:
   Sets akurateImportMessage to "File format not recognized. No
   Akurate fields could be read. Please enter actuals manually."
   Sets akurateImportMessageType to 'error'.

   If 1 or more fields found:
   Maps found fields to state:
   isoGallons   → actualISOGallons via setActuals
   resinGallons → actualResinGallons via setActuals
   For totalLbs, isoTemp, resinTemp, isoPressure, resinPressure,
   and jobNumber: append to projectNotes under a header
   "--- Akurate Import Data ---" if that header does not already
   exist in projectNotes. Format each field as "Label: value" on
   its own line using these labels:
     totalLbs      → "Total Lbs"
     isoTemp       → "ISO Temp (F)"
     resinTemp     → "Resin Temp (F)"
     isoPressure   → "ISO Pressure (PSI)"
     resinPressure → "Resin Pressure (PSI)"
     jobNumber     → "Job #"
   Sets akurateImportMessage to "Imported [N] field(s) from
   Akurate log: [comma-separated list of matched field names]."
   Sets akurateImportMessageType to 'success'.

   In both cases, clear akurateImportMessage after 8 seconds.
   Reset the file input value after reading so the same file
   can be re-imported if needed.

4. In the Actual Results Input section, add an "Import from
   Akurate Log" button in the section header row, positioned to
   the right of the "Actual Results Input" heading. Style it as
   a small secondary button using the existing gray border style
   used elsewhere in the file for secondary actions. The button
   triggers a hidden file input accepting .csv, .txt, and .log

5. Directly below the "Import from Akurate Log" button area,
